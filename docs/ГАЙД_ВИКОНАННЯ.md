# Покроковий гайд виконання лабораторної роботи №2

Цей архів містить готовий код проєкту та документацію. Історію Git (коміти, гілки,
Pull Request, Issues, реліз) кожна команда має створити **сама** на GitHub —
саме це перевіряє викладач і саме це потрібно показати на захисті.
Нижче — точна послідовність дій.

Позначки: **[ВСІ]** — виконує кожен учасник, **[TL]** — team lead, **[У1]…[У4]** — конкретний учасник.

---

## Крок 1. Команда та планування

1. Впишіть ПІБ і GitHub-логіни в таблицю «Команда» в `README.md`.
2. Ролі: Учасник 1 — team lead, Учасники 2–3 — developers, Учасник 4 — QA.
3. Розподіл модулів — таблиця «Можливості» в `README.md`.

## Крок 2. Налаштування Git [ВСІ]

```bash
git --version

git config --global user.name "Ім'я Прізвище"
git config --global user.email "email@example.com"
git config --global init.defaultBranch main
git config --global pull.rebase false
git config --global core.editor "code --wait"   # VS Code як редактор
git config --list                               # перевірка
```

GitHub: зареєструватися → **Settings → Password and authentication → Enable two-factor authentication**.

SSH-ключ:

```bash
ssh-keygen -t ed25519 -C "email@example.com"
cat ~/.ssh/id_ed25519.pub
# скопіювати вивід → GitHub → Settings → SSH and GPG keys → New SSH key
ssh -T git@github.com
# очікувано: Hi <username>! You've successfully authenticated...
```

Тренувальна вправа (рівень 1):

```bash
mkdir git-practice && cd git-practice
git init
echo "# Git practice" > README.md
git status
git add README.md
git commit -m "docs: add README"
echo "Другий рядок" >> README.md
git add README.md
git commit -m "docs: extend README"
git log --oneline
ls -la .git          # структура репозиторію: objects, refs, HEAD, config
```

📸 Скріншоти: `git --version`, `git config --list`, `ssh -T`, `git log --oneline`.

## Крок 3. Спільний репозиторій [TL]

1. GitHub → **New repository** → назва `python-utils`, **Public**, БЕЗ README/.gitignore (порожній).
2. Розпакувати архів, перейти в папку проєкту. Спочатку закомітити лише базову структуру:

```bash
cd python-utils
git init
git add README.md .gitignore CHANGELOG.md .github/ docs/
git commit -m "docs: initial commit"
git branch -M main
git remote add origin git@github.com:USERNAME/python-utils.git
git push -u origin main
```

3. **Settings → Collaborators → Add people** — додати всіх учасників (і викладача, якщо репозиторій приватний). Кожен приймає запрошення з пошти.

> Файли `main.py`, `utils/`, `tests/` поки НЕ комітьте — їх додаватимуть учасники через свої гілки.
> Щоб передати їх учасникам, скиньте кожному його файл окремо (або весь архів).

## Крок 5. Робота в гілках [ВСІ]

Кожен учасник (приклад для У2):

```bash
git clone git@github.com:USERNAME/python-utils.git
cd python-utils
git switch -c feature/converter
mkdir -p utils
# скопіювати utils/__init__.py (лише один учасник, напр. У1) та свій utils/converter.py
git add utils/converter.py
git commit -m "feat(converter): add length and mass conversion"
# за бажанням — ще один коміт, напр. температура:
git commit -am "feat(converter): add temperature conversion"
git push -u origin feature/converter
```

Рекомендовані гілки та коміти:

| Учасник | Гілка | Коміти |
|---------|-------|--------|
| У1 | `feature/calculator` | `feat(calculator): add basic operations`, `feat: add main menu` |
| У2 | `feature/converter` | `feat(converter): add unit conversion` |
| У3 | `feature/password-generator` | `feat(password): add password generator` |
| У4 | `feature/text-stats` | `feat(text): add text statistics`, `test: add unit tests` |

## Крок 6. Pull Request і code review [ВСІ]

1. GitHub покаже кнопку **Compare & pull request** → створити PR у `main`.
2. В описі (шаблон підставиться сам) вказати `Closes #2` (номер свого Issue).
3. Праворуч **Reviewers** → обрати колегу (QA переглядає всі PR).
4. Рецензент: вкладка **Files changed** → залишити хоча б один коментар → **Review changes → Approve**.
5. Автор PR (або TL) → **Merge pull request** → **Delete branch**.
6. Локально:

```bash
git switch main
git pull
git branch -d feature/converter
```

> Бажано: **Settings → Branches → Add rule** для `main` → «Require a pull request before merging» (1 approval).

## Крок 7. Навчальний конфлікт [У1 + У2]

```bash
# обидва
git switch main && git pull

# У1
git switch -c docs/readme-title-a
# змінити 1-й рядок README.md на:  # Python Utils — набір утиліт команди
git commit -am "docs: update README title"
git push -u origin docs/readme-title-a
# створити PR → злити в main

# У2 (паралельно, від тієї ж main)
git switch -c docs/readme-title-b
# змінити 1-й рядок README.md на:  # Python Utils — консольні інструменти
git commit -am "docs: change README title"
git push -u origin docs/readme-title-b
# створити PR → GitHub покаже "This branch has conflicts"
```

Вирішення (У2):

```bash
git switch docs/readme-title-b
git fetch origin
git merge origin/main
git status                    # README.md — both modified
# відкрити README.md у VS Code → Accept Both / Resolve in Merge Editor
# залишити один варіант, напр.:  # Python Utils — набір консольних утиліт команди
# переконатися, що маркерів <<<<<<< ======= >>>>>>> не лишилося
git add README.md
git commit -m "fix: resolve merge conflict in README.md"
git push
```

PR оновиться, конфлікт зникне → review → merge.

📸 Скріншоти: вивід `git status` з конфліктом, файл із маркерами, редактор злиття VS Code, змерджений PR.

## Крок 8. VS Code (рівень 3)

Показати хоча б частину роботи через GUI:
- **Source Control (Ctrl+Shift+G)**: `+` біля файлу = `git add`, поле повідомлення + ✓ = `git commit`, **Sync Changes** = push/pull.
- Нижній лівий кут — назва гілки → клік → **Create new branch** / перемикання.
- Конфлікт: кнопки **Accept Current / Incoming / Both**, **Resolve in Merge Editor**.
- Рекомендовані розширення: GitLens, GitHub Pull Requests.

## Крок 9. Перевірка .gitignore

```bash
python -m unittest discover   # створить __pycache__
git status                    # __pycache__ НЕ має з'являтися
git check-ignore -v utils/__pycache__
```

## Крок 10. Реліз v1.0.0 [TL]

Після злиття всіх PR:

```bash
git switch main && git pull
# вписати сьогоднішню дату в CHANGELOG.md
git commit -am "docs: update CHANGELOG for v1.0.0"
git push
git tag -a v1.0.0 -m "Release v1.0.0"
git push origin v1.0.0
```

GitHub → **Releases → Draft a new release** → Tag: `v1.0.0` → Title: `v1.0.0` →
**Generate release notes** (або скопіювати розділ з CHANGELOG.md) → **Publish release**.

## Крок 11. Звіти та здача

1. Кожен учасник копіює `reports/lab02-report-draft.md` у `reports/lab02-report-<прізвище>.md`,
   заповнює своїми даними й скріншотами та додає через власний PR.
   (Якщо викладач дав офіційний шаблон — переносіть текст у нього.)
2. Посилання на репозиторій → відповідь у Moodle.
3. Підготуватися до захисту: `docs/ВІДПОВІДІ_НА_КОНТРОЛЬНІ.md`.
